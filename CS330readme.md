# CS330 Computational Graphics and Visualization

## How I Approach Designing Software

This course pushed me to think visually before writing any code. Before placing an object in the scene, I had to consider its position, scale, and how light would interact with it. Working through the 3D scene taught me to break a complex visual goal into discrete components: geometry, texture, material, and lighting are all separate layers that have to work together. That layered thinking applies to any software design problem, not just graphics. In future projects I'll approach UI and system design the same way: identify the layers, build each one cleanly, and integrate.

## How I Approach Developing Programs

The milestone structure forced iteration in a way that felt natural. Each module added one capability, so the codebase never got overwhelming. When something broke, the scope was narrow enough to isolate quickly. The biggest shift in how I write code came from working with the SceneManager pattern: separating scene setup from rendering logic made the code easier to reason about and debug. That separation of concerns is something I'll apply to future projects regardless of the language or framework.

## How Computer Science Helps Me Reach My Goals

Computational graphics gave me hands-on experience with how rendering pipelines work, which connects directly to my interest in HCI and frontend development. Understanding coordinate systems, transformations, and how color and light interact gives me a stronger foundation for working with any visual interface, whether that's a data visualization library or a design tool. This course also reinforced that working at a lower level of abstraction is a skill worth having, especially when building interfaces that need to perform well visually.
